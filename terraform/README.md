# Terraform — CCC BookStack AWS footprint

Provisions the AWS production environment for the CCC internal wiki. Flat root module, one file
per concern. **Validated (`terraform validate`) but not yet applied** — applying is the AWS phase,
gated on the VUIT inputs below. See [../docs/architecture.md](../docs/architecture.md) for the design.

## What this creates

VPC (2 AZs, public+private) · single NAT + S3 gateway endpoint · VPN managed prefix list · 4 SGs ·
internet-facing **ALB** (HTTPS, ACM) gated to VPN CIDRs · **EC2** `t4g.small` in an ASG(1) running
BookStack via docker-compose · **RDS MySQL 8.0** `db.t4g.small` Multi-AZ (RDS-managed master secret) ·
**EFS** for media (`/config`) · **AWS Backup** (RDS + EFS) · Secrets Manager + SSM · least-priv IAM
instance role (+ SSM Session Manager) · CloudWatch logs + alarms + SNS.

## Prerequisites (out of band)

1. **AWS account + role** for `terraform apply` (VUIT-managed account; region confirmed).
2. **State bucket** created manually (see [backend.tf](backend.tf)); copy `backend.hcl.example` → `backend.hcl`.
3. **VUIT inputs** (see [../docs/runbooks/vuit-coordination-checklist.md](../docs/runbooks/vuit-coordination-checklist.md)):
   - `vpn_ingress_cidrs` — **the access control**. Empty = ALB is fully closed (fails safe).
   - `domain_name` + either `certificate_arn` (imported Sectigo / pre-issued ACM — recommended when
     VUIT owns DNS) or `route53_zone_id` (only if the zone is in this account).

## Apply order

```bash
cp backend.hcl.example backend.hcl       # edit
cp terraform.tfvars.example terraform.tfvars   # edit (vpn_ingress_cidrs, domain, cert, alarm_email)
terraform init -backend-config=backend.hcl
terraform plan -out tf.plan
terraform apply tf.plan
```

Then, in order (details in the runbooks):
1. **Phase 1:** apply with `auth_method=standard`. Take a manual RDS snapshot before first real use.
   Use the `saml_sp_urls` / `acm_dns_validation_records` / `alb_dns_name` outputs for VUIT.
2. **Phase 2 (SSO):** VUIT registers the SP + releases attributes; populate the SAML Secrets Manager
   secrets and SSM params; set `auth_method=saml2`; roll the ASG (`aws ec2 ... start-instance-refresh`
   or terminate the instance) so user-data re-reads config. Validate login + break-glass.
3. **Phase 3:** run the DR restore drill; confirm alarms; WCAG pass.

## Not managed by Terraform (deliberately)

VUIT DNS records (unless `route53_zone_id` set) · SAML SP registration + attribute release ·
acquiring the VPN CIDRs · the manual state bucket · BookStack version upgrades (snapshot-first runbook).

## Notes

- **Secrets** (`APP_KEY`, break-glass admins) are generated by Terraform and stored in Secrets Manager
  + state (state is encrypted in S3). SAML certs are placeholder secrets you populate in Phase 2
  (`ignore_changes` keeps your value). The RDS master password is RDS-managed (native rotation).
- **Health check** is `/icon.png` (DB-free static asset) so an RDS failover does not churn the instance.
- **No `0.0.0.0/0` ingress** anywhere; ALB ingress is the VPN prefix list only.
- Re-validate locally: `docker run --rm -v "$PWD":/wd -w /wd hashicorp/terraform:1.9 validate`
  (after `init -backend=false`).
