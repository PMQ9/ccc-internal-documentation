| 2026-06-07 | Contact-service review hardening (PR #43 follow-ups). Reliability/UX: submit now uses **Post/Redirect/Get** (303 → `/contact/thanks`) and the send runs on a background context, so a refresh/Back or a client disconnect can't duplicate or falsely fail an email (delivery is at-least-once); SMTP sends now honor an I/O deadline so a black-holing relay fails fast. Security: a cross-site **Origin/Referer** check backs the CSRF token, and `/readyz` now **fails** when `CONTACT_TRUST_PROXY=true` without `CONTACT_SECURE_COOKIE=true` (no cleartext CSRF cookie in prod). The global circuit-breaker now counts **would-be-sends** (charged after validation) instead of raw attempts, so junk can't lock out real users. Accessibility: an error re-render gets a `role="alert"` summary, `aria-invalid`/`aria-describedby`, and focus moves to the first error. Ops: a container **HEALTHCHECK** (`contact -healthcheck`, distroless-safe), and one wide structured log event per request. CI/fitness functions: `GO_IMG` is now pin-locked across Makefile/CI/Dockerfile/`go.mod`, a new gate asserts the cross-origin theme-bridge contract stays identical in both copies, and CI runs `gofmt`/`go vet`/`go test -race` plus a weekly CVE scan of the contact image | #43 |

| 2026-06-07 | Contact-form abuse hardening (issue #41) — the form is the most-attacked surface, so: a 64 KiB request-body cap before parsing (413 on oversize); a global hourly circuit-breaker across all IPs plus a daily cap on the GitHub channel (email still sends if the issue is skipped); `X-Forwarded-For` is now read from the trusted **right** (configurable hops) and validated as an IP, so a client can't forge it to evade limits or spoof the audit IP, and the rate-limiter map self-evicts so spoofed keys can't exhaust memory. Also closes attack surfaces beyond #41's spam scope: GitHub-issue fields are wrapped verbatim in code fences (no `@mention`/`#ref`/image/markup injection into the tracker), responses carry CSP + nosniff + `frame-ancestors`/Referrer-Policy, and the attacker-controlled `User-Agent` is truncated in the notification email. New knobs `CONTACT_GLOBAL_RATE_LIMIT_PER_HOUR` / `CONTACT_GITHUB_DAILY_CAP` / `CONTACT_TRUSTED_PROXY_HOPS`; new Go + `08_contact.bats` coverage. Optional CAPTCHA + CSP nonce deferred to a follow-up | — |

| 2026-06-07 | Light/dark theme now bridges the wiki and the cross-port contact page, both ways (issue #39). The wiki's theme script writes its choice to a host-scoped `ccc-color-scheme` cookie (not just `localStorage`) — cookies are scoped by host, not port, so the choice reaches the contact page on `:8081` (and same-origin in prod), which `localStorage` can't do. The contact service reads the cookie **server-side** and renders the initial `html.dark-mode`/`ccc-light` class (no light-then-dark flash), gained its own masthead theme toggle (mirrors the wiki's icons/labels), and now resolves cookie → localStorage → OS like the wiki. Cookie is `SameSite=Lax`, `Secure` under HTTPS, non-`HttpOnly` (non-sensitive, client-owned), separate from the contact `ccc_csrf` cookie. New Go + `08_contact.bats` checks assert a `dark` cookie yields `html.dark-mode` | — |
